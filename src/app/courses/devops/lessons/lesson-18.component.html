Installer k3s sur le VPS

k3s est une distribution Kubernetes certifiée CNCF, optimisée pour les environnements à ressources limitées. Un seul binaire de ~70 MB qui inclut tout : containerd, Traefik, CoreDNS. Parfait pour un VPS.

Pré-requis VPS
  • Ubuntu 22.04+ ou Debian 12+
  • Minimum 4 GB RAM (8 GB recommandé pour tout héberger)
  • 2 vCPU minimum
  • Accès root ou sudo
  • Ports ouverts : 6443 (API), 80 (HTTP), 443 (HTTPS)

Étape 1 : Installation

Terminal - VPS (SSH)
# Installer k3s (dernière version stable)
curl -sfL https://get.k3s.io | sh -s - \
  --disable traefik \
  --write-kubeconfig-mode 644

# --disable traefik : on utilisera NGINX Ingress Controller à la place
# --write-kubeconfig-mode 644 : rend le kubeconfig lisible sans sudo
Pourquoi désactiver Traefik ?

k3s inclut Traefik par défaut comme Ingress Controller. On le désactive pour installer NGINX Ingress Controller qui est plus documenté, plus utilisé en entreprise, et compatible avec les annotations que vous verrez dans les manifestes.

Étape 2 : Configurer kubectl

Terminal - VPS
# k3s place son kubeconfig ici :
# /etc/rancher/k3s/k3s.yaml

# Copier vers l'emplacement standard
mkdir -p ~/.kube
cp /etc/rancher/k3s/k3s.yaml ~/.kube/config
chmod 600 ~/.kube/config

# Vérifier que kubectl fonctionne
kubectl get nodes

# Résultat attendu :
# NAME         STATUS   ROLES                  AGE   VERSION
# mon-vps      Ready    control-plane,master   30s   v1.31.x+k3s1

Étape 3 : Vérifier le cluster

Terminal - VPS
# Vérifier tous les pods système
kubectl get pods -n kube-system

# Résultat attendu (tous en Running) :
# NAME                                      READY   STATUS    RESTARTS   AGE
# coredns-xxx                               1/1     Running   0          1m
# local-path-provisioner-xxx                1/1     Running   0          1m
# metrics-server-xxx                        1/1     Running   0          1m

# Vérifier les informations du cluster
kubectl cluster-info

# Résultat attendu :
# Kubernetes control plane is running at https://127.0.0.1:6443
# CoreDNS is running at https://127.0.0.1:6443/api/v1/...
k3s est prêt

En une seule commande, vous avez un cluster Kubernetes complet avec containerd, CoreDNS, Metrics Server et un provisioner de stockage local. Comparé à kubeadm qui nécessite 20+ étapes de configuration.

Créer les namespaces

Les namespaces isolent logiquement les environnements dans un même cluster. Chaque namespace a ses propres Deployments, Services, Secrets et quotas de ressources.

k8s/base/namespace.yaml
---
apiVersion: v1
kind: Namespace
metadata:
  name: dev
  labels:
    env: dev
---
apiVersion: v1
kind: Namespace
metadata:
  name: staging
  labels:
    env: staging
---
apiVersion: v1
kind: Namespace
metadata:
  name: prod
  labels:
    env: prod
Terminal - Appliquer
# Créer les 3 namespaces
kubectl apply -f k8s/base/namespace.yaml

# Vérifier
kubectl get namespaces

# Résultat :
# NAME              STATUS   AGE
# default           Active   5m
# dev               Active   5s
# kube-system       Active   5m
# prod              Active   5s
# staging           Active   5s

Structure Kustomize - Base + Overlays

Kustomize (intégré nativement dans kubectl) permet de gérer les variations entre environnements sans dupliquer les manifestes. Le principe : une base/ commune et des overlays/ qui patchent uniquement ce qui change.

Le fichier kustomization.yaml de base

k8s/base/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

resources:
  - namespace.yaml
  - backend-deployment.yaml
  - backend-service.yaml
  - frontend-deployment.yaml
  - frontend-service.yaml
  - postgres-statefulset.yaml
  - postgres-service.yaml
  - redis-deployment.yaml
  - redis-service.yaml
  - ingress.yaml

Overlay de production

k8s/overlays/prod/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: prod

resources:
  - ../../base
  - hpa.yaml

patches:
  - path: patches/backend-replicas.yaml
  - path: patches/resource-limits.yaml
k8s/overlays/prod/patches/backend-replicas.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: backend
spec:
  replicas: 3
k8s/overlays/dev/kustomization.yaml
apiVersion: kustomize.config.k8s.io/v1beta1
kind: Kustomization

namespace: dev

resources:
  - ../../base

patches:
  - target:
      kind: Deployment
    patch: |
      - op: replace
        path: /spec/replicas
        value: 1

Déployer par environnement

Terminal
# Prévisualiser ce que Kustomize va générer
kubectl kustomize k8s/overlays/dev

# Déployer en dev
kubectl apply -k k8s/overlays/dev

# Déployer en staging
kubectl apply -k k8s/overlays/staging

# Déployer en production
kubectl apply -k k8s/overlays/prod

# Vérifier un déploiement spécifique
kubectl get all -n prod
kubectl apply -k vs kubectl apply -f

-f applique un fichier YAML brut. -k utilise Kustomize pour fusionner la base avec l'overlay avant d'appliquer. C'est la méthode recommandée pour les environnements multiples.
