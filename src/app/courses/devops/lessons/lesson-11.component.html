Prometheus - Architecture

  ┌──────────────────────────────────────────────┐
  │              Prometheus Server                │
  │  ┌──────────┐ ┌──────────┐ ┌──────────────┐  │
  │  │ Retrieval │ │  TSDB    │ │  HTTP Server │  │
  │  │ (scrape)  │ │ (stockage│ │  (PromQL)    │  │
  │  └─────┬─────┘ └──────────┘ └──────┬───────┘  │
  └────────┼─────────────────────────────┼─────────┘
           │                             │
    ┌──────▼──────┐               ┌──────▼──────┐
    │  Targets    │               │   Grafana   │
    │ Spring Boot │               │ (dashboards)│
    │ /actuator/  │               └─────────────┘
    │ prometheus  │
    └─────────────┘

Prometheus fonctionne en pull : il interroge (scrape) les endpoints des applications à intervalle régulier.

Instrumenter Spring Boot avec Micrometer

pom.xml - dépendances
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-actuator</artifactId>
</dependency>
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-registry-prometheus</artifactId>
</dependency>
application.yml
management:
  endpoints:
    web:
      exposure:
        include: health, info, prometheus, metrics
  metrics:
    tags:
      application: my-api

Métriques custom

OrderService.java
@Service
public class OrderService {{ '{' }}

    private final Counter ordersCounter;
    private final Timer orderProcessingTimer;

    public OrderService(MeterRegistry registry) {{ '{' }}
        this.ordersCounter = Counter.builder("app_orders_total")
            .description("Total des commandes traitées")
            .tag("service", "order-service")
            .register(registry);

        this.orderProcessingTimer = Timer.builder("app_order_duration_seconds")
            .description("Durée de traitement d'une commande")
            .register(registry);
    {{ '}' }}

    public OrderResponse processOrder(OrderRequest request) {{ '{' }}
        return orderProcessingTimer.record(() -> {{ '{' }}
            ordersCounter.increment();
            // Logique métier...
            return new OrderResponse(/* ... */);
        {{ '}' }});
    {{ '}' }}
{{ '}' }}

Déployer Prometheus sur K8s

bash - via Helm
# Ajouter le repo Helm
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# Installer le stack complet (Prometheus + Grafana + Alertmanager)
helm install monitoring prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --create-namespace \
  --set grafana.adminPassword='ChangeMe123!'
servicemonitor.yaml - Scraper Spring Boot
apiVersion: monitoring.coreos.com/v1
kind: ServiceMonitor
metadata:
  name: api-backend-monitor
  namespace: monitoring
spec:
  selector:
    matchLabels:
      app: api-backend
  namespaceSelector:
    matchNames:
      - production
  endpoints:
    - port: http
      path: /actuator/prometheus
      interval: 15s

PromQL - Requêtes essentielles

PromQL
# Taux de requêtes HTTP par seconde (5 dernières minutes)
rate(http_server_requests_seconds_count[5m])

# Latence P99
histogram_quantile(0.99, rate(http_server_requests_seconds_bucket[5m]))

# Taux d'erreurs 5xx
sum(rate(http_server_requests_seconds_count{{ '{' }}status=~"5.."{{ '}' }}[5m]))
  / sum(rate(http_server_requests_seconds_count[5m]))

# Utilisation mémoire JVM
jvm_memory_used_bytes{{ '{' }}area="heap"{{ '}' }}
  / jvm_memory_max_bytes{{ '{' }}area="heap"{{ '}' }}

Grafana - Dashboards

Grafana se connecte à Prometheus comme source de données et permet de créer des dashboards visuels.

Dashboards recommandés
  • JVM (Micrometer) - ID: 4701 - Mémoire, GC, threads
  • Spring Boot - ID: 12900 - HTTP, cache, DB pool
  • K8s Cluster - ID: 6417 - Nodes, pods, namespaces
  • NGINX Ingress - ID: 9614 - Trafic, latence, erreurs

Importez-les via le menu Dashboards → Import avec l'ID correspondant.

Travaux Pratiques - Prometheus & Grafana sur Kind

Prérequis : Cluster Kind k8s-lab et Helm installé. Ce lab installe une stack de monitoring complète en quelques commandes grâce au chart kube-prometheus-stack.

Lab Stack Prometheus + Grafana avec Helm ~25 min

Objectifs

  • Installer Helm et ajouter le repo Prometheus
  • Déployer la stack de monitoring sur le cluster
  • Accéder à Grafana et explorer les dashboards pré-configurés
  • Visualiser les métriques CPU/mémoire de vos pods en temps réel

Étape 1 - Installer Helm

bash - Linux
curl https://raw.githubusercontent.com/helm/helm/main/scripts/get-helm-3 | bash
helm version
bash - macOS
brew install helm
helm version
PowerShell - Windows
choco install kubernetes-helm
helm version

Étape 2 - Installer kube-prometheus-stack

bash
# Ajouter le repo Helm
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm repo update

# Créer le namespace monitoring
kubectl create namespace monitoring

# Installer la stack complète (Prometheus + Grafana + AlertManager + node-exporter)
helm install prometheus-stack prometheus-community/kube-prometheus-stack \
  --namespace monitoring \
  --set grafana.adminPassword=admin \
  --set prometheus.prometheusSpec.podMonitorSelectorNilUsesHelmValues=false

# Attendre que tout soit prêt (peut prendre 2-3 minutes)
kubectl get pods -n monitoring -w

Étape 3 - Accéder à Grafana

bash
# Port-forward vers Grafana
kubectl port-forward -n monitoring service/prometheus-stack-grafana 3000:80

# Ouvrir http://localhost:3000
# Login : admin / admin

# Dashboards pré-installés utiles :
# - "Kubernetes / Compute Resources / Cluster"  (CPU/mémoire globale)
# - "Kubernetes / Compute Resources / Pod"      (par pod)
# - "Kubernetes / Nodes"                        (métriques des nodes)

Étape 4 - Accéder à Prometheus

bash
# Port-forward vers Prometheus
kubectl port-forward -n monitoring service/prometheus-stack-kube-prom-prometheus 9090:9090

# Ouvrir http://localhost:9090
# Essayer ces requêtes PromQL :

# CPU utilisé par tous les pods
sum(rate(container_cpu_usage_seconds_total[5m])) by (pod)

# Mémoire utilisée par namespace
sum(container_memory_usage_bytes) by (namespace)

# Nombre de pods en Running
kube_pod_status_phase{phase="Running"}
✓ Résultat attendu

Grafana s'ouvre sur localhost:3000 avec des dashboards Kubernetes pré-configurés. Vous visualisez en temps réel le CPU, la mémoire et l'état de vos pods. Prometheus exécute vos premières requêtes PromQL.
