Pourquoi cette leçon ?

Avant de plonger dans l'architecture de Kubernetes, vous devez disposer d'un environnement opérationnel. Cette leçon couvre les trois outils indispensables — kubectl, Kind et Docker Desktop — ainsi que les commandes kubectl du quotidien et la création d'un cluster local multi-nodes. À la fin, vous aurez un cluster Kubernetes fonctionnel sur votre machine.

Outils requis

Trois outils sont nécessaires pour suivre les leçons Kubernetes qui suivent. Si vous ne les avez pas encore, installez-les via le Lab 0 en bas de cette page, puis revenez à la lecture.

Outil Rôle Version minimale Vérification
Docker Desktop Moteur de conteneurs - requis par Kind pour simuler les nodes K8s 24.x docker version
kubectl CLI officiel Kubernetes - toutes les commandes kubectl … passent par lui 1.28+ kubectl version --client
Kind Crée un cluster K8s complet en local via des conteneurs Docker 0.22+ kind version
Docker Desktop doit être actif

Kind utilise Docker pour créer les nodes du cluster. Si Docker n'est pas en cours d'exécution, toutes les commandes kind et la plupart des commandes kubectl échoueront. Vérifiez que l'icône Docker est active dans votre barre système avant de continuer.

Environnements cloud - pas besoin de Kind

Si vous travaillez directement sur GKE, EKS ou AKS, kubectl suffit. Configurez simplement votre kubeconfig avec les credentials du cluster cloud (gcloud container clusters get-credentials, aws eks update-kubeconfig, etc.) et toutes les commandes des leçons suivantes fonctionnent sans modification.

kubectl - Maîtriser l'outil de commande

kubectl est le CLI qui communique avec l'API Server via votre fichier ~/.kube/config (le kubeconfig). Il supporte plusieurs contextes (clusters) entre lesquels vous pouvez basculer.

bash - Gestion des contextes et clusters
# Voir tous les contextes disponibles (clusters configurés)

kubectl config get-contexts



# Basculer vers un autre cluster

kubectl config use-context production-gke



# Voir le contexte actuel

kubectl config current-context



# Informations sur le cluster

kubectl cluster-info
bash - Commandes essentielles du quotidien
# -- LISTER --------------------------------------------

kubectl get pods                         # Pods du namespace courant

kubectl get pods -n production           # Pods d'un namespace spécifique

kubectl get pods -A                      # Pods de tous les namespaces

kubectl get pods -o wide                 # + colonnes IP et node

kubectl get pods -l app=api-backend      # Filtrer par label

kubectl get all                          # Pods + services + deployments + replicasets



# -- INSPECTER -----------------------------------------

kubectl describe pod api-backend-7d4f9   # Détails complets + events (très utile pour debug)

kubectl describe node worker-1           # État d'un node + ressources allouées



# -- LOGS ----------------------------------------------

kubectl logs api-backend-7d4f9           # Logs du conteneur principal

kubectl logs api-backend-7d4f9 -f        # Suivi en temps réel (follow)

kubectl logs api-backend-7d4f9 -c api    # Logs d'un conteneur spécifique (multi-container pod)

kubectl logs api-backend-7d4f9 --previous  # Logs avant le dernier crash



# -- EXECUTER ------------------------------------------

kubectl exec -it api-backend-7d4f9 -- /bin/sh   # Shell interactif

kubectl exec api-backend-7d4f9 -- env            # Lister les variables d'env



# -- APPLIQUER / SUPPRIMER -----------------------------

kubectl apply -f deployment.yaml         # Créer ou mettre à jour (idempotent)

kubectl delete -f deployment.yaml        # Supprimer depuis un fichier

kubectl delete pod api-backend-7d4f9     # Supprimer un pod (sera recréé par le Deployment)



# -- DEBUG AVANCÉ --------------------------------------

# Pod éphémère de debug sur le même node qu'un pod en panne

kubectl debug -it api-backend-7d4f9 --image=busybox --target=api



# Port-forward pour accéder à un pod localement (sans Service)

kubectl port-forward pod/api-backend-7d4f9 8080:8080

kubectl port-forward service/api-backend-service 8080:80
Alias incontournables pour le quotidien 
alias k='kubectl'

alias kgp='kubectl get pods'

alias kgpa='kubectl get pods -A'

alias kd='kubectl describe'

alias kl='kubectl logs'

alias kaf='kubectl apply -f'



# Auto-complétion (bash)

source <(kubectl completion bash)

complete -F __start_kubectl k

Installation locale avec Kind

Kind (Kubernetes in Docker) crée un cluster K8s complet en utilisant des conteneurs Docker comme nœuds. C'est l'outil recommandé pour développer et tester localement sans avoir besoin d'un cloud ou de VMs supplémentaires.

kind-config.yaml - Cluster multi-nodes avec port mapping
kind: Cluster

apiVersion: kind.x-k8s.io/v1alpha4

name: dev-cluster

nodes:

  - role: control-plane

    # Expose le port 80 du node sur localhost:80 pour l'Ingress

    extraPortMappings:

      - containerPort: 80

        hostPort: 80

      - containerPort: 443

        hostPort: 443

  - role: worker

  - role: worker
bash - Linux
curl -Lo ./kind https://kind.sigs.k8s.io/dl/v0.22.0/kind-linux-amd64

chmod +x ./kind

sudo mv ./kind /usr/local/bin/kind

kind version
bash - macOS
brew install kind

kind version
PowerShell - Windows
choco install kind

# Ou manuellement :

curl.exe -Lo kind.exe https://kind.sigs.k8s.io/dl/v0.22.0/kind-windows-amd64

Move-Item .\kind.exe C:\Windows\System32\kind.exe

kind version
bash - Commandes Kind (tous OS)
# Créer le cluster depuis la config

kind create cluster --config kind-config.yaml



# Vérifier que les 3 nodes sont Ready

kubectl get nodes

# NAME                        STATUS   ROLES           AGE   VERSION

# dev-cluster-control-plane   Ready    control-plane   60s   v1.29.0

# dev-cluster-worker          Ready    <none>          45s   v1.29.0

# dev-cluster-worker2         Ready    <none>          45s   v1.29.0



# Charger une image locale dans les nodes Kind (évite de la pusher sur un registry)

kind load docker-image myregistry/api-backend:1.0.0 --name dev-cluster



# Supprimer le cluster

kind delete cluster --name dev-cluster
Alternatives à Kind

minikube - Plus simple, une seule commande, avec un dashboard web intégré. Moins adapté aux configurations multi-nodes.
k3d - Basé sur k3s (distribution K8s allégée), démarrage très rapide, excellent pour les pipelines CI.
Docker Desktop - Intègre un cluster K8s mono-node, pratique mais limité.

Travaux Pratiques - Mise en place de l'environnement

Objectif global : Passer de zéro à un cluster Kubernetes fonctionnel sur votre machine. Vous allez installer les outils, puis créer un cluster multi-nodes avec Kind. Aucun cloud requis — tout tourne en local. Ce cluster servira de base à toutes les leçons suivantes.

Lab 1 Créer votre premier cluster Kind ~10 min

Objectifs

  • Créer un cluster 1 control-plane + 2 workers
  • Vérifier l'état des nodes
  • Comprendre le kubeconfig généré automatiquement

Étape 1 - Créer le fichier de config

Créez un fichier kind-cluster.yaml à la racine de votre projet :

kind-cluster.yaml
kind: Cluster

apiVersion: kind.x-k8s.io/v1alpha4

name: k8s-lab



nodes:

  - role: control-plane

    # Expose le port 80 du cluster sur localhost:8080

    extraPortMappings:

      - containerPort: 80

        hostPort: 8080

        protocol: TCP

  - role: worker

  - role: worker

Étape 2 - Lancer le cluster

bash
kind create cluster --config kind-cluster.yaml



# Sortie attendue :

# Creating cluster "k8s-lab" ...

#  ✓ Ensuring node image (kindest/node:v1.29.0)

#  ✓ Preparing nodes (1 control-plane, 2 workers)

#  ✓ Writing configuration

#  ✓ Starting control-plane

#  ✓ Installing CNI

#  ✓ Installing StorageClass

#  ✓ Joining worker nodes

# Set kubectl context to "kind-k8s-lab"

Étape 3 - Explorer le cluster

bash
# Les 3 nodes doivent être Ready

kubectl get nodes

# NAME                     STATUS   ROLES           AGE

# k8s-lab-control-plane    Ready    control-plane   90s

# k8s-lab-worker           Ready    <none>          70s

# k8s-lab-worker2          Ready    <none>          70s



# Voir les composants système (Control Plane en pods !)

kubectl get pods -n kube-system

# Vous verrez : coredns, etcd, kube-apiserver, kube-scheduler, kube-proxy...



# Infos du cluster

kubectl cluster-info
Kind crée les nœuds du cluster comme des conteneurs Docker

Vérifiez avec docker ps : vous verrez 3 conteneurs (k8s-lab-control-plane, k8s-lab-worker, k8s-lab-worker2). Chaque conteneur simule une machine réelle avec un kubelet, containerd et tous les composants K8s.

✅ Résultat attendu

kubectl get nodes affiche 3 nodes en statut Ready. Votre contexte kubectl est automatiquement configuré sur ce cluster. Vous êtes prêt pour la leçon suivante : Architecture Kubernetes.
