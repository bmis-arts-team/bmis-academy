Pourquoi les Services ?

Les pods sont éphémères : leurs adresses IP changent à chaque redémarrage. Un Service fournit une adresse stable pour accéder à un groupe de pods, sélectionnés par labels.

  Service "api-service" (ClusterIP: 10.96.42.15)
         │
         ├──▶ Pod api-backend-abc12  (10.244.1.5)
         ├──▶ Pod api-backend-def34  (10.244.2.8)
         └──▶ Pod api-backend-ghi56  (10.244.1.12)

ClusterIP - Communication interne

Le type par défaut. Le service est accessible uniquement depuis l'intérieur du cluster.

clusterip-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: api-service
spec:
  type: ClusterIP
  selector:
    app: api-backend
  ports:
    - port: 80
      targetPort: 8080
      protocol: TCP

Accessible via : api-service.default.svc.cluster.local:80

NodePort & LoadBalancer

NodePort - Accès depuis l'extérieur (dev)

Expose le service sur un port statique (30000-32767) de chaque node.

nodeport-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: api-nodeport
spec:
  type: NodePort
  selector:
    app: api-backend
  ports:
    - port: 80
      targetPort: 8080
      nodePort: 30080

LoadBalancer - Production

Provisionne automatiquement un load balancer cloud (AWS ALB/NLB, GCP LB, Azure LB).

loadbalancer-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: api-lb
spec:
  type: LoadBalancer
  selector:
    app: api-backend
  ports:
    - port: 443
      targetPort: 8080

Headless Service

Un service avec clusterIP: None. Utilisé pour les StatefulSets car il permet d'accéder directement à chaque pod individuel via DNS.

headless-service.yaml
apiVersion: v1
kind: Service
metadata:
  name: postgres-headless
spec:
  clusterIP: None
  selector:
    app: postgres
  ports:
    - port: 5432

Chaque pod est accessible individuellement : postgres-0.postgres-headless.default.svc.cluster.local

Ingress Controller

L'Ingress gère le routage HTTP/HTTPS depuis l'extérieur vers les services internes. Il remplace plusieurs LoadBalancers par un seul point d'entrée.

ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: app-ingress
  annotations:
    nginx.ingress.kubernetes.io/rewrite-target: /
    nginx.ingress.kubernetes.io/rate-limit: "100"
spec:
  ingressClassName: nginx
  tls:
    - hosts:
        - api.example.com
      secretName: api-tls-secret
  rules:
    - host: api.example.com
      http:
        paths:
          - path: /api
            pathType: Prefix
            backend:
              service:
                name: api-service
                port:
                  number: 80
          - path: /
            pathType: Prefix
            backend:
              service:
                name: frontend-service
                port:
                  number: 80
Ingress Controller requis

L'objet Ingress seul ne fait rien. Vous devez installer un Ingress Controller (NGINX, Traefik, HAProxy, etc.) dans le cluster. NGINX est le plus courant :

bash
kubectl apply -f https://raw.githubusercontent.com/kubernetes/ingress-nginx/controller-v1.10.0/deploy/static/provider/cloud/deploy.yaml

TLS/HTTPS avec cert-manager

cert-manager automatise l'obtention et le renouvellement des certificats TLS via Let's Encrypt.

cluster-issuer.yaml
apiVersion: cert-manager.io/v1
kind: ClusterIssuer
metadata:
  name: letsencrypt-prod
spec:
  acme:
    server: https://acme-v02.api.letsencrypt.org/directory
    email: devops@example.com
    privateKeySecretRef:
      name: letsencrypt-prod-key
    solvers:
      - http01:
          ingress:
            class: nginx

Ajoutez l'annotation cert-manager.io/cluster-issuer: letsencrypt-prod à votre Ingress pour activer le TLS automatique.
