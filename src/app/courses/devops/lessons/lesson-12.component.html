Networking Kubernetes - Les bases

Kubernetes impose un modèle réseau flat : chaque pod reçoit sa propre adresse IP et peut communiquer avec n'importe quel autre pod du cluster sans NAT.

CommunicationMécanisme
Pod → Pod (même node)Bridge Linux (cbr0)
Pod → Pod (nodes différents)CNI plugin (Calico, Cilium, Flannel)
Pod → Servicekube-proxy (iptables / IPVS)
Extérieur → ServiceIngress Controller / LoadBalancer

Service Discovery via DNS

Kubernetes fournit un DNS intégré (CoreDNS). Chaque service est accessible par son nom :

Formats DNS
# Format court (même namespace)
postgres-service

# Format complet (FQDN)
postgres-service.production.svc.cluster.local

# Pour un StatefulSet (pod individuel)
postgres-0.postgres-headless.production.svc.cluster.local

Network Policies - Le firewall de K8s

Par défaut, tous les pods peuvent communiquer entre eux. Les Network Policies permettent de restreindre le trafic réseau (ingress et/ou egress).

CNI requis

Les Network Policies ne fonctionnent que si le CNI les supporte. Calico et Cilium les supportent. Flannel ne les supporte pas nativement.

Deny all - Politique par défaut

deny-all.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: deny-all
  namespace: production
spec:
  podSelector: {{ '{' }}{{ '}' }}    # Sélectionne tous les pods
  policyTypes:
    - Ingress
    - Egress

Autoriser le trafic sélectif

allow-api-to-db.yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-api-to-postgres
  namespace: production
spec:
  podSelector:
    matchLabels:
      app: postgres
  policyTypes:
    - Ingress
  ingress:
    - from:
        - podSelector:
            matchLabels:
              app: api-backend
      ports:
        - protocol: TCP
          port: 5432

RBAC - Contrôle d'accès

Le Role-Based Access Control définit qui peut faire quoi dans le cluster.

rbac.yaml
# Rôle limité à un namespace
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: developer
  namespace: staging
rules:
  - apiGroups: [""]
    resources: ["pods", "services", "configmaps"]
    verbs: ["get", "list", "watch"]
  - apiGroups: ["apps"]
    resources: ["deployments"]
    verbs: ["get", "list", "watch", "update"]
---
# Lier le rôle à un utilisateur
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: developer-binding
  namespace: staging
subjects:
  - kind: User
    name: alice
    apiGroup: rbac.authorization.k8s.io
roleRef:
  kind: Role
  name: developer
  apiGroup: rbac.authorization.k8s.io
Principe du moindre privilège

Ne donnez jamais cluster-admin aux comptes de service applicatifs. Limitez chaque rôle au strict nécessaire (namespace, ressources, verbes).

Pod Security Standards

Kubernetes définit trois niveaux de sécurité pour les pods :

NiveauDescriptionUsage
PrivilegedAucune restrictionComposants système uniquement
BaselineRestrictions minimalesApplications standard
RestrictedRestrictions maximalesWorkloads sensibles
namespace-security.yaml
apiVersion: v1
kind: Namespace
metadata:
  name: production
  labels:
    pod-security.kubernetes.io/enforce: baseline
    pod-security.kubernetes.io/warn: restricted
