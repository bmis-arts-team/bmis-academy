Pourquoi le CDN est crucial

Un CDN (Content Delivery Network) distribue votre contenu statique (JS, CSS, images, fonts) depuis des serveurs edge proches de l'utilisateur final. Avantages :

  • Latence réduite - Le contenu est servi depuis le point de présence le plus proche
  • Charge réduite - Le backend n'a plus à servir les fichiers statiques
  • Résilience - Les assets restent disponibles même si le backend est surchargé
  • Performance - Compression (Brotli, gzip), HTTP/2, optimisation automatique

Comment fonctionne un CDN

  Utilisateur (Paris)                    Utilisateur (Tokyo)
       │                                       │
       ▼                                       ▼
  ┌─── Edge Paris ───┐                  ┌─── Edge Tokyo ──┐
  │ Cache local      │                  │ Cache local      │
  │ (JS, CSS, img)   │                  │ (JS, CSS, img)   │
  └────────┬─────────┘                  └────────┬─────────┘
           │ cache miss                          │ cache miss
           ▼                                     ▼
      ┌─────────────────────────────────────────────┐
      │          Origin Server (votre backend)       │
      └─────────────────────────────────────────────┘

Headers de cache

Cache-Control headers
# Assets buildés (hash dans le nom) - cache long
Cache-Control: public, max-age=31536000, immutable
# Exemple: main.a1b2c3d4.js

# index.html - toujours revalider
Cache-Control: no-cache, must-revalidate
# Le navigateur vérifie toujours avec le serveur

# API responses - pas de cache CDN
Cache-Control: private, no-store

Servir une SPA Angular via CDN

Build de production

bash
ng build --configuration production
# Résultat dans dist/my-app/browser/
# Les fichiers JS/CSS ont un hash : main.a1b2c3d4.js

Upload vers un bucket cloud

bash - AWS S3
# Sync des fichiers buildés vers S3
aws s3 sync dist/my-app/browser/ s3://my-app-frontend/ \
  --cache-control "public, max-age=31536000, immutable"

# index.html sans cache (pour les mises à jour)
aws s3 cp dist/my-app/browser/index.html s3://my-app-frontend/index.html \
  --cache-control "no-cache, must-revalidate"

Configurer CloudFront

Créez une distribution CloudFront pointant vers le bucket S3 avec le fallback index.html pour le routing Angular (SPA).

Alternative : NGINX + CDN

nginx.conf
server {{ '{' }}
    listen 80;
    server_name app.example.com;
    root /usr/share/nginx/html;
    index index.html;

    # SPA fallback
    location / {{ '{' }}
        try_files $uri $uri/ /index.html;
    {{ '}' }}

    # Cache long pour les assets hashés
    location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff2?)$ {{ '{' }}
        expires 1y;
        add_header Cache-Control "public, immutable";
    {{ '}' }}

    # Pas de cache pour index.html
    location = /index.html {{ '{' }}
        add_header Cache-Control "no-cache, must-revalidate";
    {{ '}' }}

    # Compression
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1000;
{{ '}' }}
