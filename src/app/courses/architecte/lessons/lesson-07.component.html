Cahier Pratique Final - TaskFlow Entreprise

Ce cahier pratique rassemble les exercices finaux du cours. Chaque exercice met en pratique un pattern ou une technologie abordée dans les chapitres précédents, appliquée au projet TaskFlow.

Kafka Topics - Vue d'ensemble

TopicProducteur → ConsommateurAction déclenchée
task-created task-service → notification-service Envoi notification + mise à jour cache
task-assigned task-service → notification-service Notification utilisateur assigné
project-updated project-service → task-service Synchronisation des métadonnées projet

Exercice 1 - Kafka Event : TaskCreated

Objectif : Implémenter le flux complet d'un événement Kafka de bout en bout.

  1. Dans task-service, publier un événement TaskCreated sur le topic task-created après la création d'une tâche
  2. Dans notification-service, créer un consommateur Kafka qui écoute le topic task-created
  3. Le consommateur doit envoyer une notification à l'utilisateur assigné
  4. Mettre à jour le cache Redis avec la nouvelle tâche
  5. Vérifier dans les logs que la notification a bien été envoyée et le cache mis à jour
Indice

Utilisez projectId comme clé de partition Kafka pour garantir l'ordre des événements d'un même projet.

Exercice 2 - SAGA : Rollback distribué

Objectif : Implémenter une SAGA avec compensation en cas d'échec.

  1. Créer une tâche dans task-service qui nécessite une validation du project-service
  2. Le project-service vérifie que le projet existe et accepte de nouvelles tâches
  3. Simuler une panne du project-service (retourner une erreur 500)
  4. Vérifier que le task-service effectue le rollback : suppression de la tâche créée
  5. Vérifier que le notification-service n'envoie pas de notification pour une tâche annulée
Attention

La compensation doit être idempotente : si le rollback est rejoué (réseau instable), le résultat doit être le même.

Exercice 3 - CQRS : Séparation lecture/écriture

Objectif : Séparer les flux de lecture et d'écriture avec cache Redis.

  1. Créer deux services distincts : TaskCommandService (écriture) et TaskQueryService (lecture)
  2. Le TaskCommandService écrit dans PostgreSQL et publie un événement Kafka
  3. Le TaskQueryService lit depuis le cache Redis en priorité
  4. Implémenter l'endpoint GET /tasks/project/{{ '{' }}id{{ '}' }} qui sert les données depuis Redis sans toucher la base
  5. Vérifier que le cache est invalidé quand une nouvelle tâche est créée

Exercice 4 - Circuit Breaker : Resilience4j

Objectif : Protéger un service avec un Circuit Breaker.

  1. Ajouter Resilience4j au notification-service pour les appels vers le service d'email externe
  2. Configurer le Circuit Breaker : seuil d'échec à 50%, durée d'ouverture à 30 secondes
  3. Implémenter un fallback qui enregistre la notification en file d'attente
  4. Simuler une panne du service d'email (timeout, erreur 503)
  5. Vérifier que le circuit s'ouvre après les échecs et que le fallback prend le relais
  6. Vérifier que le task-service continue de fonctionner normalement malgré la panne email

Exercice 5 - Monitoring : Prometheus + Grafana

Objectif : Mettre en place un monitoring complet des microservices.

  1. Activer l'endpoint /actuator/prometheus sur tous les services
  2. Configurer Prometheus pour scraper les métriques de chaque service (scrape interval : 15s)
  3. Créer un dashboard Grafana avec les panels suivants :
    • Requêtes HTTP par seconde (par service)
    • Latence P95 et P99
    • Taux d'erreurs (4xx et 5xx)
    • Usage mémoire JVM (heap / non-heap)
  4. Configurer une alerte Alertmanager si la latence P99 dépasse 2 secondes

Exercice 6 - Tracing distribué : Jaeger

Objectif : Tracer une requête à travers tous les microservices.

  1. Ajouter l'instrumentation OpenTelemetry à chaque service Spring Boot
  2. Configurer l'export des traces vers Jaeger
  3. Créer une tâche via l'API et tracer le flux complet :
    • API Gateway → task-service → project-service (vérification)
    • task-service → Kafka → notification-service
    • task-service → Redis (mise en cache)
  4. Visualiser la trace complète dans l'interface Jaeger
  5. Identifier les goulots d'étranglement (spans les plus longs)
