1.1 - Pourquoi la plupart des backends deviennent ingérables

Un backend mal structuré accumule rapidement de la dette technique. Les symptômes sont reconnaissables :

  • Classes trop longues - des fichiers de 500+ lignes mélangeant logique métier, accès données et validation
  • Dépendances difficiles à gérer - modifier un service casse trois autres
  • Modifications cassantes - chaque feature introduit des régressions
  • Difficulté à tester - impossible d'écrire un test unitaire sans monter toute la base
  • Peur de toucher au code - personne n'ose refactorer
Le vrai problème

Ce n'est pas un manque de compétence technique - c'est un manque de structure. Sans architecture claire, même les meilleurs développeurs produisent du code difficile à maintenir.

1.2 - Séparer les responsabilités

Les architectures modernes comme la Clean Architecture et l'architecture hexagonale partagent un principe fondamental : chaque couche a une responsabilité unique et les dépendances pointent toujours vers le centre (le domaine métier).

Principe clé

Chaque partie du système doit avoir un rôle clair et unique. Le domaine métier ne doit jamais dépendre de l'infrastructure.

         ┌──────────────────────────────────┐
         │           Web / API              │  ← Controllers, DTOs
         ├──────────────────────────────────┤
         │         Application              │  ← Use Cases, orchestration
         ├──────────────────────────────────┤
         │           Domaine                │  ← Entités, règles métier
         ├──────────────────────────────────┤
         │        Infrastructure            │  ← JPA, HTTP clients, messaging
         └──────────────────────────────────┘

         Les dépendances pointent vers le centre (Domaine)

1.3 - Structure professionnelle avec Spring Boot

Structure classique (à éviter en projet complexe)

Structure classique
com.example.taskflow/
├── controller/
├── service/
├── repository/
└── entity/

Cette structure fonctionne pour de petits projets, mais elle mélange les responsabilités dès que le projet grandit.

Structure professionnelle

domain/

Entités métier, règles de validation, logique pure. Aucune dépendance Spring.

application/

Use cases, orchestration des opérations métier. Dépend uniquement du domaine.

infrastructure/

Implémentations techniques : JPA, clients HTTP, messaging, configuration.

web/

Controllers REST, DTOs de requête/réponse. Point d'entrée HTTP.

Structure professionnelle
com.example.taskflow/
├── domain/
│   ├── model/          ← Entités métier (Task, Project, User)
│   └── repository/     ← Interfaces (ports)
├── application/
│   ├── usecase/        ← CreateTaskUseCase, AssignTaskUseCase
│   └── dto/            ← CreateTaskRequest, TaskResponse
├── infrastructure/
│   └── persistence/    ← JpaTaskRepository, JpaProjectRepository
└── web/
    ├── controller/     ← TaskController, ProjectController
    └── exception/      ← GlobalExceptionHandler

1.4 - Exemple concret : création d'une tâche

❌ Approche naïve

Tout dans le contrôleur : validation, accès base, logique métier mélangés.

✅ Approche professionnelle

Chaque couche a sa responsabilité. Le contrôleur délègue au use case.

❌ Anti-pattern : tout dans le contrôleur

TaskController.java - Anti-pattern
@RestController
@RequestMapping("/api/tasks")
public class TaskController {{ '{' }}

    @Autowired
    private TaskRepository taskRepository;

    @PostMapping
    public Task createTask(@RequestBody Task task) {{ '{' }}
        // Pas de validation
        // Pas de vérification du projet
        // Entité JPA exposée directement
        return taskRepository.save(task);
    {{ '}' }}
{{ '}' }}

✅ Approche professionnelle

1. DTO de requête (web/)

CreateTaskRequest.java
public record CreateTaskRequest(
    @NotBlank(message = "Le titre est obligatoire")
    @Size(max = 100, message = "Le titre ne doit pas dépasser 100 caractères")
    String title,

    String description,

    @NotNull(message = "Le projet est obligatoire")
    Long projectId
) {{ '{' }} {{ '}' }}

2. Use Case (application/)

CreateTaskUseCase.java
@Service
@RequiredArgsConstructor
public class CreateTaskUseCase {{ '{' }}

    private final TaskRepository taskRepository;
    private final ProjectRepository projectRepository;

    public Task execute(CreateTaskRequest request) {{ '{' }}
        Project project = projectRepository.findById(request.projectId())
            .orElseThrow(() -> new ProjectNotFoundException(request.projectId()));

        Task task = Task.builder()
            .title(request.title())
            .description(request.description())
            .status(TaskStatus.TODO)
            .project(project)
            .build();

        return taskRepository.save(task);
    {{ '}' }}
{{ '}' }}

3. Contrôleur (web/)

TaskController.java
@RestController
@RequestMapping("/api/tasks")
@RequiredArgsConstructor
public class TaskController {{ '{' }}

    private final CreateTaskUseCase createTaskUseCase;

    @PostMapping
    public ResponseEntity<Task> createTask(@Valid @RequestBody CreateTaskRequest request) {{ '{' }}
        Task task = createTaskUseCase.execute(request);
        return ResponseEntity.status(HttpStatus.CREATED).body(task);
    {{ '}' }}
{{ '}' }}

Gestion centralisée des erreurs

GlobalExceptionHandler.java
@RestControllerAdvice
public class GlobalExceptionHandler {{ '{' }}

    @ExceptionHandler(ProjectNotFoundException.class)
    public ResponseEntity<ErrorResponse> handleNotFound(ProjectNotFoundException ex) {{ '{' }}
        ErrorResponse error = new ErrorResponse(
            HttpStatus.NOT_FOUND.value(),
            ex.getMessage(),
            LocalDateTime.now()
        );
        return ResponseEntity.status(HttpStatus.NOT_FOUND).body(error);
    {{ '}' }}

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public ResponseEntity<ErrorResponse> handleValidation(MethodArgumentNotValidException ex) {{ '{' }}
        String message = ex.getBindingResult().getFieldErrors().stream()
            .map(e -> e.getField() + ": " + e.getDefaultMessage())
            .collect(Collectors.joining(", "));

        ErrorResponse error = new ErrorResponse(
            HttpStatus.BAD_REQUEST.value(),
            message,
            LocalDateTime.now()
        );
        return ResponseEntity.badRequest().body(error);
    {{ '}' }}
{{ '}' }}

Sécurité JWT et Spring Security

Le flux d'authentification JWT suit un schéma classique en deux temps :

Client ──POST /login──> AuthController ──génère──> JWT Token
Client ──Authorization: Bearer token──> JwtFilter ──valide & injecte──> SecurityContext

Le JwtFilter intercepte chaque requête, valide le token et injecte l'utilisateur authentifié dans le SecurityContext de Spring Security.

1.6 - Erreurs classiques à éviter

❌ Erreur✅ Bonne pratique
Exposer les entités JPA dans les réponses API Utiliser des DTOs de réponse dédiés
Mettre la logique métier dans les contrôleurs Déléguer aux use cases (couche application)
Ignorer la validation des entrées Utiliser @Valid + Bean Validation
Pas de gestion centralisée des erreurs Implémenter un @RestControllerAdvice
Pas de tests unitaires Tester chaque use case avec Mockito

Exemple de test unitaire

CreateTaskUseCaseTest.java
@ExtendWith(MockitoExtension.class)
class CreateTaskUseCaseTest {{ '{' }}

    @Mock
    private TaskRepository taskRepository;

    @Mock
    private ProjectRepository projectRepository;

    @InjectMocks
    private CreateTaskUseCase useCase;

    @Test
    void shouldCreateTaskSuccessfully() {{ '{' }}
        // Given
        Project project = new Project(1L, "Mon Projet", "Description");
        when(projectRepository.findById(1L)).thenReturn(Optional.of(project));
        when(taskRepository.save(any(Task.class))).thenAnswer(inv -> inv.getArgument(0));

        CreateTaskRequest request = new CreateTaskRequest("Ma tâche", "Description", 1L);

        // When
        Task result = useCase.execute(request);

        // Then
        assertThat(result.getTitle()).isEqualTo("Ma tâche");
        assertThat(result.getStatus()).isEqualTo(TaskStatus.TODO);
        verify(taskRepository).save(any(Task.class));
    {{ '}' }}

    @Test
    void shouldThrowWhenProjectNotFound() {{ '{' }}
        // Given
        when(projectRepository.findById(99L)).thenReturn(Optional.empty());
        CreateTaskRequest request = new CreateTaskRequest("Tâche", "Desc", 99L);

        // When / Then
        assertThatThrownBy(() -> useCase.execute(request))
            .isInstanceOf(ProjectNotFoundException.class);
    {{ '}' }}
{{ '}' }}
